Improve the existing Ai-Aether meeting assistant codebase with the following enhancements, preserving all current functionality and the existing architecture:
Frontend refactoring: Split the monolithic frontend/app.js into modular ES6 files organized by responsibility: a websocket.js module for connection handling, a charts.js module for all Chart.js rendering logic, a transcript.js module for live transcript and search, a history.js module for history panel management, a document.js module for document upload and unit rendering, a demo.js module for the scripted demo mode, and a main.js entry point that wires them together. Use native ES6 imports with <script type="module"> so no build step is required. Keep all existing DOM IDs and CSS class names intact so the HTML and styles.css do not need to change.
Salesforce session hardening: Enhance backend/salesforce_client.py to detect expired sessions by catching SalesforceExpiredSession and generic auth errors on every query, then transparently re-authenticate and retry once. Add a configurable session timeout check that proactively refreshes the session if it has been idle for more than 30 minutes. Log all reconnection events clearly so users can diagnose auth issues.
Dynamic Salesforce stage detection: Modify backend/entities.py to remove hardcoded Salesforce stage names from the system prompt. At startup, query the Salesforce org's OpportunityStage picklist values using the describe API, cache them in memory, and inject the actual org-specific stage list into the Claude prompt dynamically. This ensures the system works correctly for orgs with custom pipeline stages.
WebSocket backpressure handling: Add rate limiting to backend/hub.py so that slow clients don't block the broadcast loop. Implement a per-client bounded send queue with a maximum depth of 50 messages. When a client's queue is full, drop the oldest non-critical events (transcripts and entities) while always preserving topic_shift and error events. Log when messages are dropped for a specific client.
Connection resilience: Add automatic WebSocket reconnection logic to the frontend with exponential backoff starting at 1 second and capping at 30 seconds. Show a clear reconnecting indicator in the status badge. Preserve the last known topic state across reconnections so the UI doesn't flash empty during brief network blips.
Configuration validation: Enhance backend/config.py to validate API keys at startup by making lightweight test calls to the Anthropic API and Salesforce before the pipeline starts. Fail fast with a clear, actionable error message if any credential is invalid, rather than letting the user discover it mid-meeting.
Observability: Add a structured logging setup using Python's logging module with configurable log levels via a LOG_LEVEL environment variable. Add request IDs to every pipeline event so a single audio chunk can be traced through transcription, context evaluation, entity extraction, Salesforce querying, and broadcasting in the logs.
Graceful degradation: If Salesforce is unavailable, continue running transcription, topic detection, and entity extraction, but show a clear banner in the UI explaining that CRM data is offline. The assistant should still be useful as a transcription and topic tracker even without Salesforce connectivity.
Testing: Add unit tests for the new Salesforce session refresh logic, WebSocket backpressure behavior, and configuration validation. Mock external APIs appropriately. Keep the existing test suite passing.
Do not remove or alter the existing demo mode, document upload pipeline, SQLite persistence, settings panel, or atomic file save logic. Keep the project runnable with the same one-command setup scripts. Update the README to document any new environment variables and behavioral changes.
